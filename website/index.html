От сервера до ноды

Подключение с проверкой
реальной работы.

01 / INSTALL

Один SSH-доступ

Установка k0s worker, WireGuard и systemd-сервисов. SSH-ключ сервера закреплён; администраторский kubeconfig остаётся у вас.

02 / CONNECT

Сеть под контролем CNI

Изолированная сеть Worker соединяется с gateway-агентами. CNI кластера — Calico, Flannel, Cilium или kube-router — по-прежнему управляет Pod-маршрутами, IPAM и инкапсуляцией.

03 / VERIFY

Ready — начало проверки

Тестовые Pod проверяют трафик с каждым исходным Worker. Нода открывается для workloads после успешных проверок.

Как это работает

Снаружи — VDS.
Внутри — ваш Worker.

Один существующий control plane. Обычные Pod, kubelet и scheduler. Шифрованная связь между площадками.

  1. Проверить и посмотреть планСовместимость, SSH fingerprint и план изменений до установки.
  2. Установить аддонDeployment управляет подключением; gateway-агенты работают на текущих Workers.
  3. Получить проверенную нодуКраткоживущий bootstrap token отзывается, начальный taint снимается после тестов.
Разобраться в сетевой схеме →
terminal / quick startk8nnect
# Проверить кластер и SSH без изменений
$ k8nnect connect-check \
    --config connection.json \
    --kubeconfig cluster.yaml

# Установить управляющий аддон
$ k8nnect addon-install \
    --config connection.json \
    --kubeconfig cluster.yaml

# После установки и проверок
$ kubectl get node k8nnect-vds
NAME           STATUS   VERSION
k8nnect-vds     Ready    v1.36.4+k0s

Честные границы

Проверенные профили.
Понятная архитектура.

Четыре CNI проверены на живых кластерах; несовместимые настройки установщик отвергает, а не меняет. Полную независимость от CNI не обещаем.

Расширение одного кластера и соединение независимых кластеров — разные задачи. Сейчас реализовано подключение Worker к одному кластеру.
