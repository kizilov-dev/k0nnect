01 / INSTALL

Start with SSH access

k0s worker, WireGuard, and systemd services are installed for you. The SSH host key is pinned. Your admin kubeconfig stays with you.

02 / CONNECT

Your CNI stays in charge

An isolated worker network connects to gateway agents. Calico, Flannel, Cilium, or kube-router keeps control of Pod routing, IPAM, and encapsulation.

03 / VERIFY

Ready is just the beginning

Test Pods check traffic against every existing worker. The new node accepts workloads only after verification succeeds.

How it works

A server outside.
Your worker inside.

One existing control plane. Standard Pods, kubelet, and scheduler. Encrypted connectivity between locations.

  1. Install the controllerOne kubectl apply: a CRD, static RBAC you can review, and a Deployment. Nothing to build.
  2. Describe the serverA VDSConnection with the address and pinned SSH fingerprint, plus an SSH Secret. Gateway agents start on your existing workers.
  3. Get a verified workerThe short-lived bootstrap token is revoked. The initialization taint is removed after workload tests pass.

terminal / quick startk0nnect
# Install the controller
$ kubectl apply -f \
    https://github.com/kizilov-dev/k0nnect/releases/latest/download/install.yaml

# Add SSH access and describe the server
$ kubectl -n k0nnect-system create secret \
    generic vds-ssh --from-file=private-key=id_ed25519
$ kubectl apply -f vdsconnection.yaml

# After installation and verification
$ kubectl get node k0nnect-vds
NAME           STATUS   VERSION
k0nnect-vds     Ready    v1.36.4+k0s

Illustrative output. See the guide for prerequisites and SSH setup.
